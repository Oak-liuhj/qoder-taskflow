## 前置条件与运行方式

- 测试机器安装 Node.js ≥24.9.0，node 在 PATH 中可启动。
- Qoder 支持本项目的 Plugin、Hooks、MCP stdio 和 MCP Apps；原生独立聊天工具须在当前客户端实际发现。
- taskflow MCP 通过 node runtime/server.cjs 运行，依赖已随包提供，无在线服务地址、额外模型 Key 或本插件专用登录账号。
- 原生聊天执行使用当前 Qoder 账号与宿主模型；其可用权限、产品支持与网络连接以当前环境为准。
- 使用独立测试项目、测试会话和测试账本，避免修改生产计划。不要在证据中包含账号凭据或模型私有推理。

## 待补：本次正式包实机完整工作流

以下步骤为实际验收用例，尚未在本次 0.1.0 正式包上执行。请执行后填写结果并附截图或演示。

1. 通过 Qoder“扩展 → 插件 → 添加插件 → 上传插件”导入上述 ZIP。按宿主提示重新加载，记录安装结果、插件版本、组件和 MCP Ready 状态。
2. 在独立测试项目新建会话，打开右侧 Apps → 任务。确认未混入其他会话计划，保存空状态截图。
3. 输入“使用 Taskflow，建立两个事项：检查 23×29；校验前项结果。第二项依赖第一项，本轮只规划”。确认实际调用 taskflow_plan，清单在聊天和右侧显示，任务标题、依赖与状态相符。
4. 继续执行第一项，核对 progress、complete 的持久结果。确认第二项按依赖可启动，界面、工具状态与结果一致；保存完整流程截图。
5. 另建单事项 delegate 测试计划，用原生 create_chat_session(callbackMode:supervise) 创建可见子会话。核对子会话自身 claim → progress → complete、真实 sessionId、attemptId、version，以及父会话回调、读取和通知确认。不得由父会话代交。
6. 切换会话，验证面板隔离；重新打开同一计划，确认 ID、要求和结果保留。检查深浅主题、树形展开、任务详情与刷新。

## 历史观察与已知限制

- 2026-11-18 至 2026-11-19 的开发版在 Qoder Desktop 0.5.14 上已有 Hook、面板自动绑定、单事项原生可见子聊天和完成回调证据，详见 docs/qoder-adaptation.md；不将其标为 0.1.0 正式 ZIP 的重新验收。
- 历史 Windows ZIP 导入在校验通过后出现目录重命名 EPERM，曾经用户授权手动安装；本轮正式包尚未确认正常导入是否成功。
- 多层原生聊天委派、跨设备执行和真实中断恢复尚未实机验证。
- 右上固定聊天工具栏按钮、左侧原生会话缩进不属于当前插件已实现功能。
- 会话面板元数据 com.qoder/turnContext.sessionId 是 Qoder 0.5.14 的实测兼容接口，其他版本应实际验证。
